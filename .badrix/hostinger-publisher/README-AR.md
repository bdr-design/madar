# BADRIX — مزامنة Hostinger

تعمل هذه النسخة عبر PHP CLI وCron على باقة Single، وتبقي الجامع وسجله خارج public_html. لا تحتاج مفاتيح SFTP أو توكنًا للمصادر العامة.

- فك الحزمة في مجلد الموقع الذي يحتوي public_html؛ ينتج مجلد شقيق باسم badrix-sync.
- الأمر المجدول يشغّل badrix-sync/sync.php بواسطة PHP 8.1 أو أحدث مع امتداد cURL.
- المخرج العام الوحيد: public_html/data/development.json.
- المصادر والفروع: sources.json، مع ترقيم صفحات كل الفروع وقراءة السجلات من بصمات ثابتة. مصادر عامة فقط؛ إذا تعذر الوصول إلى مصدر يتوقف النشر وتبقى آخر لقطة.
- سجل كل لعبة: .badrix/public-journal.json. يلزم تحديث الأحداث عند إنجاز التطوير؛ لا تستنتج الأرقام من عدد commits.
- خطط النسبة والتواريخ واللقطة التاريخية المعتمدة: curated-ledger.json. تبقى التغطية جزئية حتى مراجعة كامل التاريخ.
- التاريخ الدائم والذاكرة المؤقتة والحالة الفنية: state/ خارج المجلد العام. احتفظ بهذا المجلد عند تحديث الجامع، ولا تستبدله بنسخة قديمة.
- يستخدم الجمع API لفهرس الفروع، وraw.githubusercontent.com لملفات السجل العامة، مع ذاكرة للرؤوس الثابتة. يمنع ذلك استهلاك حد API على ملف كل فرع في الجولة الأولى.
- يختبر الجامع 31 حالة مرجعية قبل كل نشر، منها مطابقة لقطة الألعاب الثلاث، ومنع تكرار الإنجازات، والتحقق من الأدلة والتواريخ والنسب، وتنقيح روابط المصادر من العرض.
- الكتابة ذرية إلى ملف مؤقت ثم إعادة تسمية، مع قفل يمنع تداخل التشغيلات.
- الجدول المقصود: كل 30 دقيقة، وقراءة صفحة الزائر للنتيجة كل 5 دقائق. أول تشغيل وتشغيل الجولة التالية مطلوبان لإثبات الاتصال والجدولة.

آخر حالة نشر فعلية موجودة في state/status.json، ولا تظهر للزوار. يحتوي فشل الجمع على رسالة فنية ويحتفظ باللقطة العامة السابقة.
